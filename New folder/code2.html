#RFC-001: Distributed Caching Strategy

Status: [Draft] Author: @dev_lead Date: 2023-10-27 edit Edit Source

##Context

Currently, our monolith hits the primary database for every read operation. This causes significant latency during peak traffic hours (1800-2100 UTC).

##Proposal

We propose introducing a distributed caching layer using Redis to offload read traffic. This aligns with ref:DECISION-102 regarding our infrastructure modernization.

###Implementation Details

  1. 1. Provision Redis Cluster (v7.0)
  2. 2. Update ORM middleware to check cache before DB query.
  3. 3. Implement Write-Through strategy for consistency.

##Trade-offs

  • - **Complexity**: Adds another component to manage.
  • - **Consistency**: Potential for stale data if invalidation fails (see ref:DECISION-41 for TTL standards).
